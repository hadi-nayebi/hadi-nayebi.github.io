The original private Claude Seed is frozen. Seed Agent is the new public implementation: Codex provides the runtime, while the user-owned cognition around it is rebuilt from the behavioral lessons of the reference rather than copied from its Bash code or Claude-specific file structure.

What the Frozen Reference Contributes

The Claude Seed remains useful because these behaviors were exercised together through real work. They are study targets for the Codex implementation, not a checklist that must survive unchanged.

Continuity

Persistent Jobs

Long-running work carries identity, history, state, dependencies, completion logic, and context beyond one chat session.

Cognition

Phasic Work

The reference used OPEVC — Observe, Plan, Execute, Verify, Condense — to compartmentalize cognition. Codex Seed will reconsider the exact phase system rather than assuming five phases are universal.

Context

Local Working Memory

The reference combined stable instruction and dynamic memory in CLAUDE.md. The Codex foundation explicitly separates those roles before defining a new working-memory contract.

Behavior

Plugins and Guards

Bounded behaviors with state, interfaces, sensing, guidance, deterministic controls, tests, and recovery remain strong abstraction candidates, but their Codex anatomy is not frozen yet.

Codex boundary

The Seed lives around Codex, not inside a Codex fork.

Codex supplies the model/session/tool runtime. The current project focuses on the reusable cognitive layer and the user/job layer around it. Native Codex primitives should be used where they already solve the problem; historical Claude workarounds are not recreated by default.

If a future capability truly cannot be guaranteed above the runtime, that becomes an explicit architectural decision rather than a starting assumption.

How a Capability Enters the New Seed

The migration unit is a behavioral objective, not a directory.

Study the Reference

Identify what problem the behavior solved, what failed before it existed, and which parts were specific to Claude Code.

Define It for Codex

Inspect Codex-native primitives, define ownership/state/interfaces/authority/recovery, and specify acceptance evidence before choosing the implementation shape.

Implement the Smallest Slice

Build one end-to-end behavior, test it, operate it, and let evidence shape the next abstraction instead of scaffolding the old plugin catalog in advance.
