Foundation stage

Architecture before broad feature translation

The public work establishes Q-Seed's identity, framework/cognition/job boundaries, authority model, working-memory direction, and reproducible Qwen Code lineage. Broad translation of the frozen Seed's cognitive features has intentionally not begun.

Foundation stage

One Agent, Three Evolving Layers

The model animates the agent. The local framework gives it a body. The plugin brain gives it reusable cognitive structure and the right amount of friction.

01Replaceable intelligence

The Model

A compatible model animates each session without becoming the identity of the agent. Model choice can evolve independently of the locally owned framework and cognitive brain.

02User-controlled body

The Qwen Code Fork

The framework lives beside the mind as its own versioned project. General runtime improvements can land there through isolated work, tests, a reviewable pull request, recovery evidence, and explicit user approval.

03Cognitive brain

.qwen/ and Plugins

Identity, context, memory behavior, jobs, phases, guards, policies, knowledge, and learned working methods belong here when they do not require permanent realization inside the framework.

Future research direction

The model can learn the harness, too

Model choice is deliberately replaceable. A future model could be fine-tuned not only for task skill, but for better intuitions about operating this harness—when to slow down, ask, challenge, verify, or introduce friction. Open-weight models such as Inkling make that direction concrete without becoming a dependency.

How One Feature Gets Built

The frozen Claude Seed supplies evidence. Q-Seed's written behavior contract—not historical code—guides each implementation.

  1. 1

    Study

    Observe the feature's behavior, value, friction, failure modes, and history in the reference.

  2. 2

    Consolidate

    Distill a clear definition and separate essential behavior from accidental implementation history.

  3. 3

    Define

    Write Q-Seed's own terminology, guarantees, authority, recovery, and user-visible promise.

  4. 4

    Place

    Choose the framework fork, the .qwen/ cognitive layer, the job layer, or a deliberate mixed boundary.

  5. 5

    Build

    Implement the smallest Qwen-native vertical slice from the new contract.

  6. 6

    Test and Verify

    Prove behavior, boundaries, recovery, and compatibility, record what changed, and only then continue.
