One Agent, Three Evolving Layers

The model animates the agent. The local framework gives it a body. The plugin brain gives it memory, judgment, and the right amount of friction.

01Replaceable intelligence

The Model

Qwen can animate Q-Seed today; another compatible open-weight or specialized model can animate it tomorrow. The model is powerful, but it is not the whole agent.

02Locally owned body

The Qwen Code Fork

The framework lives beside the mind as its own local project. Deeper runtime improvements can land there through a complete job, tests, a reviewable pull request, and explicit user approval.

03Cognitive Markov brain

.qwen/ and Plugins

Identity, context, memory, jobs, phases, guards, and learned working methods live here. This layer decides when to move, when to ask, when to verify, and when friction protects the work.

Future research direction

The model can learn the harness, too

Q-Seed should not be locked to one model. A future model could be fine-tuned not only for task skill, but for better intuitions about operating this harness—when to slow down, ask, challenge, verify, or introduce friction. Open-weight models such as Inkling make that direction concrete without making it a dependency.

How One Feature Gets Built

The Claude prototype is evidence. The approved Q-Seed contract—not historical code—is the implementation source.

  1. 1

    Study

    Observe the feature's behavior, value, friction, and failures in the current prototype.

  2. 2

    Consolidate

    Agree on a clear shared understanding and separate essential behavior from accidental history.

  3. 3

    Define

    Write Q-Seed's own terminology, contracts, authority, and user-visible promise.

  4. 4

    Place

    Choose the fork, a plugin, the .qwen/ mind, or a deliberate mixed boundary.

  5. 5

    Build

    Implement the smallest Qwen-native vertical slice from the new contract.

  6. 6

    Test and Verify

    Prove behavior, demonstrate it publicly, record what was learned, and only then continue.
