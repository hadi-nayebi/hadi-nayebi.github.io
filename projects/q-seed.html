Q-Seed

Q-Seed asks a deeper version of the Seed question: what changes when the user owns not only the cognitive harness, but also a maintained fork of the CLI framework underneath it?

The key difference

Codex Seed treats the CLI as the runtime. Q-Seed makes the runtime itself part of the owned architecture.

This does not mean every Q-Seed feature belongs in the fork. It means the project can place a genuinely general deterministic primitive lower when the cognitive layer cannot honestly guarantee it by itself.

Flexibility gradient

Put a capability in the most flexible layer that can honestly provide its guarantee.

The framework is deeper and more stable. The cognitive layer is more inspectable and adaptable. Job experience is the most fluid. A capability can span layers only when each layer owns a distinct part of the contract.

Framework mechanism

General interception, lifecycle, context transport, tool permission, concurrency, or enforcement primitives that should not encode Q-Seed-specific meaning.

Cognitive meaning

Why a phase exists, how a job behaves, what a guard protects, how memory should be used, and other reusable Seed-specific policy that a user should be able to inspect and evolve.

Instance experience

The particular job's objective, approvals, plans, artifacts, decisions, and lived experience. It should not silently become global policy after one successful run.

Mixed realization is allowed. For example, the fork may expose a reliable pre-mutation event, a Q-Seed plugin may define the policy that consumes it, and the active job may carry the approval state. What matters is explicit ownership rather than forcing everything into one folder.
The first architectural cleanup

Q-Seed was where the instruction/working-memory split became explicit.

The frozen Claude Seed used `CLAUDE.md` both as stable instruction and mutable phase tissue. Q-Seed began defining a runtime-neutral local working-memory concept rather than treating the runtime's instruction filename as the memory architecture.

`QWEN.md` is intended to remain a relatively stable runtime/brain orientation layer. A separate local `WM.md` is the candidate working-memory organ: its body would hold condensed directory-local memory while its dynamic surface would support temporary cognition that can later be consolidated and deflated.

The intended discovery behavior was also becoming more formal: when a tool accesses a file, the runtime could discover applicable working-memory files from the workspace boundary toward the target, inject only newly applicable context, label provenance, deduplicate it, refresh after edits, remain symlink-safe, and behave predictably under parallel tool calls.

This is a design contract, not a finished feature. The pushed Q-Seed repository explicitly says the common `WM.md` grammar should be decided and tested before automatic discovery is implemented.
Self-modification has depth

The agent can propose framework changes. It cannot silently approve its own substrate.

Q-Seed's fork is part of the organism, but deeper ownership comes with deeper review friction.

Separate histories

The Qwen Code fork and Q-Seed cognitive repository remain independently versioned. Q-Seed pins an approved framework revision rather than depending on a moving branch.

Framework PR required

A consequential runtime change should be isolated in the framework repository with its own tests, compatibility evidence, and recovery plan.

User approval remains explicit

An agent can study, propose, and prepare the change, but it does not gain authority to land a deeper framework revision simply because it authored it.

Context before implementation

Define the concept before historical code chooses the new architecture by accident.

Q-Seed's current public work is primarily architectural because the project intentionally paused broad feature translation until its layer boundaries and shared language were clear.

Study behavior and failures

Use the private reference as evidence, not implementation material.

Consolidate terminology

Define what the capability means, why it exists, its invariants, its authority boundary, and whether it is current, target, or research.

Place the guarantee

Decide framework, cognitive layer, job layer, or an explicit mixed contract.

Write acceptance evidence

Tests should follow the new contract rather than clone the historical file structure.

Implement a narrow slice

Only after ownership and behavior are clear does the code begin.

Current state

Q-Seed is an early public foundation, not a second active full-speed build.

The repository has meaningful architectural contracts and a maintained Qwen Code integration line, but broad Seed feature implementation has not begun. Current priority is the Codex Seed; Q-Seed remains the sibling experiment to return to afterward.

The value of keeping Q-Seed public now is that its different boundary already teaches something: when the runtime is open, some capabilities can be decomposed into a general mechanism below and inspectable cognitive meaning above. That comparison will become more useful after the Codex version has real implemented behaviors to compare against.
