Placement rule

Use the most flexible layer that can honestly guarantee the behavior.

Deeper code is harder to change and maintain. A capability should move into the framework only when the cognitive layer cannot reliably provide the guarantee above it.

Framework

General interception, lifecycle, permission, concurrency, or context-delivery mechanisms with no Q-Seed-specific policy.

Cognitive brain

The reusable meaning: how jobs work, what a phase means, what a guard protects, how memory should behave, and which interfaces are public.

Job experience

The user's actual objective and history. A successful one-off job should not silently become a global rule.

Mixed implementations are valid. A framework event can expose a reliable mechanism, a plugin can interpret it, and the active job can hold the specific approval state—as long as ownership stays explicit.
A useful design lesson

Q-Seed separated instruction files from working memory.

This is one of the ideas already influencing the Codex version even though Q-Seed itself is still early.

The frozen Claude Seed used CLAUDE.md for both durable local instructions and mutable OPEVC working memory. Q-Seed started defining those as two different organs: QWEN.md for stable orientation and a candidate WM.md layer for dynamic local working memory.

The intended working-memory system was moving toward explicit discovery, provenance, deduplication, refresh after edits, symlink safety, and predictable behavior during parallel tool calls. Those contracts exist as design work; the automatic feature is not implemented yet.

Deeper ownership requires stronger governance

The agent can propose a framework change. It cannot approve its own substrate.

The framework and cognitive brain have separate histories so deeper runtime work remains visible and reversible.

Separate repository

Qwen Code keeps its own version history instead of being mixed invisibly into cognitive changes.

Separate PR

Framework changes need their own tests, compatibility evidence, and recovery story.

Explicit user approval

The agent may study and prepare the change, but authorship does not grant authority to land it.

Current state

Architecture exists. Broad feature implementation does not.

Q-Seed remains public and useful as the deeper framework-ownership experiment, but the current implementation priority is Seed Agent on Codex.

Returning to Q-Seed after the Codex Seed has real behaviors will make the comparison more useful: the same behavioral objective can then be tested once above a fixed runtime and once with an open runtime available as another design layer.
