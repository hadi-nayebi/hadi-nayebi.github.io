It does not yet ship the jobs, plugins, working memory, cognitive phases, authority controls, or verification system intended for the mature Seed.

Project overview

Seed Agent is an open-source effort to make the agent harness the durable layer that becomes specific to one person's work. The current foundation defines how Codex and that future harness will meet; later stages are intended to add the ongoing jobs, memory, reusable behaviors, verification rules, authority boundaries, and learned working methods that should persist across sessions and model changes.

The project grows out of the first Hadosh Academy Seed, a Claude Code implementation where these ideas were developed together through sustained use. That reference is documented publicly across the B5–B8 technical series and is also available for private technical review, giving the Codex version a concrete architectural lineage.

The Codex generation reimplements those behaviors against Codex's own primitives and lets the implementation anatomy evolve with the runtime. The long-term goal is a mature public Seed that a person can clone, understand, and cultivate into their own digital cortex while their specific jobs, knowledge, and history stay local to their deployment.

Mission

Make the harness the user's durable AI asset.

Models and CLI runtimes can change. The cognition that becomes specific to one person's work remains inspectable, portable, and extensible outside the model session.

The project treats the LLM as the engine and the harness as the digital cortex around it. The target Seed will remember ongoing work through jobs, separate reusable behavior into plugins, compartmentalize different kinds of cognition, keep important state outside the model, and learn from completed work so the system can become more specific to its user over time.

The public repository is intended to become a general Seed that people can clone and cultivate. Each deployment then adds its own jobs, knowledge, interfaces, and optional dashboard while the public cognition layer remains generic and reusable.

Architecture

Codex is the runtime. Target Seed cognition stays inspectable above it.

The current foundation defines the boundary; later stages will implement the cognition and job layers around the runtime.

Use Codex-native primitives

When Codex already provides a reliable tool, instruction surface, sandbox rule, skill, or runtime behavior, the Seed builds on that primitive directly.

Keep cognitive meaning visible

Why a job persists, what a plugin owns, how a phase behaves, what needs verification, and who has authority remain part of the user-owned harness.

Keep interfaces flexible

The CLI is the basic personal interaction surface. A dashboard or web interface can be added when a deployment benefits from another way to interact with the same harness.

Working memory

Stable instructions and dynamic working memory become separate organs.

This planned architectural separation carries forward one of the useful ideas developed during the Q-Seed design work.

AGENTS.md

Stable scoped instructions: durable rules and local guidance.

Dynamic working memory

A separate local working-memory surface. WM.md is the current candidate name while its Codex-specific discovery, persistence, and phase behavior are designed.

Structured state

Plugin and job state stays with clear owners and interfaces, giving the agent readable prose and explicit machine state where each is most useful.
