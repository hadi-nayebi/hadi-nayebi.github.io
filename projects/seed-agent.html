Where it comes from

The Claude Seed is a frozen reference, not the codebase being shipped.

The private Hadosh Academy Seed was the first deep personal harness. It is no longer being developed, but it contains the most complete history of the behaviors that this public project is learning from.

New public implementation

Seed Agent on Codex

Each behavior is restated in platform-independent terms, compared with what Codex already provides, then implemented only if the abstraction still makes sense.

The migration unit is the behavior, not the file. Bash scripts, .claude/, CLAUDE.md footers, exact thresholds, and old plugin anatomy do not automatically come with it.
What belongs where

Codex stays the runtime. Seed cognition stays inspectable above it.

This project is intentionally different from Q-Seed: it does not begin by owning or modifying a fork of the CLI framework.

Use Codex-native primitives

If Codex already provides a reliable tool, instruction surface, sandbox rule, or runtime behavior, use it rather than recreating a Claude workaround.

Keep cognitive meaning visible

Why a job persists, how a phase behaves, what a plugin owns, what needs verification, and who has authority should remain legible in the harness.

Dashboard is optional

A personal deployment may add a dashboard for a particular use case, but the individual Seed is not defined by having one. The CLI remains the basic interaction surface.

A design improvement already carried forward

Stable instructions and dynamic working memory are separate concepts.

The Claude reference combined both roles inside directory-local CLAUDE.md files. The Codex project starts cleaner.

AGENTS.md

Stable scoped instructions: durable rules and local guidance that should not constantly inflate and deflate with active work.

WM.md — candidate

A possible future local working-memory organ. The name exists; the grammar, discovery, precedence, persistence, and phase behavior are deliberately not fixed yet.

Structured state

Plugin/job state should stay with clear owners and interfaces rather than disappearing into prose simply because the model can read it.

How the public Seed will be built

One behavior per serious PR, then learn from operation.

There is no reason to pre-create a dozen historical plugins before the first Codex-native behavior proves its shape.

Study

Understand the reference behavior, its failure modes, and why it was added.

Restate

Define the objective without Claude-specific implementation assumptions.

Inspect Codex

Identify the native primitives that already solve part of the problem.

Define the contract

Ownership, state, interfaces, authority, failure/recovery, and acceptance evidence.

Implement narrowly

Build the smallest end-to-end behavior, test it, use it, then generalize only from evidence.

Current state

The destination is clean. The mature cognition is not there yet.

The public repository has been reset as a Codex-native foundation. It is not yet a finished Seed and should not be presented as install-ready.

The next meaningful step is to select the first behavioral capability from the frozen reference and reimplement it properly on Codex. That is where the real project begins.
