Project overview

Origin removes the work every user should not have to pay an agent to recreate: a Linux, macOS, or WSL2 web surface, an interactive agent connection, persistent conversations, recovery, and a review boundary. Normal startup opens the browser, presents a short first-visit guide, and resumes the repository's newest Codex chat, starting fresh when none exists. It does not pre-decide the user's profession, pages, objects, vocabulary, or workflows.

A person normally reaches this substrate during Phases 6–7 of Start Here, after an existing agent has learned enough about them to propose the first useful pages. Codex users can adopt the public implementation directly. Other CLI agents can use the documented behavior as a porting contract rather than pretending that changing one executable name creates a compatible harness.

Origin begins as a minimal single-user foundation. Dashboard feedback is included; optional Telegram engagement works with paired remote text and media before any speech capability is installed. Local transcription and cloned-voice replies with exact readable captions are optional. Each actionable thread becomes one isolated worktree and one GitHub pull request; only the owner-facing dashboard or paired Telegram action can merge it and complete the thread.

One interactive session

A strict launcher checks Git, Node.js, tmux, Codex CLI, authentication, and WSL2 on Windows, then opens the dashboard and attaches one repository-scoped Codex session. GitHub CLI authentication supports the pull-request workflow. Startup resumes the newest repository chat or starts fresh.

Durable responsibility

Each channel saves conversation state before wake delivery. Raw input, context, messages, interpretation, isolated work, the linked PR, verification, merge acceptance, and reopening history remain inspectable and recoverable.

Compartmentalized anatomy

Neutral core + runtime

The core enforces shared lifecycle and PR-binding contracts without owning a channel. The runtime owns the loopback server, browser launch, tmux delivery, evidence, and recovery without merging channel state or cognition.

The implemented lifecycle

Conversation is saved first. Attention follows.

Neither channel relies on a transient prompt or network send as the only copy of the user's intent.

1. Persist

The user comments from a dashboard route or writes to the paired bot. The owning channel records the raw contribution and context, assigns a stable ID, and only then creates a bounded wake event.

2. Wake or queue

If Codex is idle, tmux submits an orienting voice to the same foreground session. If Codex is busy or a channel is paused, responsibility remains durable without interrupting active work.

3. Worktree and PR

The agent reads authoritative state by ID, interprets or clarifies the request, and implements it on that thread's isolated branch. Related inputs join the parent history. Verified work returns as exactly one linked GitHub PR.

4. Owner merge

The dashboard button or paired Telegram button or command asks the owner broker to merge. It checks the current thread, repository, branch, PR state, and final GitHub result before recording resolution. The trusted agent hook blocks supported self-merge paths.

Honest maturity

What 1.0 does not claim.

The release separates demonstrated machinery from the curriculum for later growth.

Origin 1.0 is single-user. Its dashboard is loopback-only; optional Telegram engagement is an outbound Bot API client, not a hosted dashboard or synchronization service. Origin does not ship accounts, team roles, a general job plugin, or a full OPEVC engine. Feedback records are the first durable work queue; they may later create or enrich jobs, but they are not quietly renamed into a job system today.

The owner-authority hook is a deterministic boundary for trusted Codex tool calls, not an operating-system sandbox against malicious code using the same account. GitHub branch protection is the stronger remote boundary. Automated tests cover lifecycle, worktree and PR binding, merge refusal, independent hooks and removal, tmux behavior, simulated Telegram transport, interface behavior, accessibility, build, and smoke paths. A fresh target machine still must prove authenticated Codex and GitHub, hook trust, browser and terminal integration, and real merge behavior. Telegram remains preview until dedicated-bot text/media, reply, merge, restart, and optional speech acceptance are complete.

Differentiation

Every clone should become less generic through use.

The common substrate removes repeated setup; the user's context decides what grows on top.

After Start Here establishes an Asset Charter and a verified web-to-CLI handoff, the helping agent proposes the smallest useful pages in the user's own terminology. Real feedback then reveals which objects deserve durable state, which repeated responsibilities deserve plugins, and which multi-cycle work deserves explicit jobs or OPEVC phases.

Later Origin versions may add proven capabilities, but version numbers do not replace local evolution. A research environment, client practice, family world, and project portfolio should not inherit the same nouns, permissions, or completion tests merely because they share a starting substrate.
