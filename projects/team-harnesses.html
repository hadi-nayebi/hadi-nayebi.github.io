Prototype pattern · small teams

Team Harnesses

A shared harness can become part of a team's operating environment without forcing every member to use one central chatbot or one identical personal agent.

Shared substrate

The team shares a private repository containing the common harness, shared context, and governed team-level behavior.

Local agents

Each member can run their own CLI agent against the same shared harness and retain individual working surfaces where appropriate.

Dashboard

A local browser dashboard gives non-terminal users a common place for jobs, questions, workflows, feedback, and review.

Governance

Shared harness changes and ordinary project content do not need the same authority. The implementation should make that distinction explicit.

Why this is a separate project

A team cortex is not just six copies of a personal cortex.

The interesting design problems are shared versus individual memory, authority, synchronization, onboarding, and how several independently operated agents stay consistent with one team-owned substrate.
