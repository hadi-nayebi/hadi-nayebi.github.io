Project overview

The Base Dashboard begins without a profession-specific world. Its purpose is to give a user and their agent a working developmental surface immediately. The user can describe what the dashboard needs from inside the dashboard, and the agent can turn those comments into visible, persistent, bounded work.

The substrate does not decide whether it becomes a movie studio, research environment, catering operation, client practice, family world, or project portfolio. Pages, terminology, objects, workflows, authority, and later plugins differentiate through the user's work.

Hadosh Academy provides the pattern and educational layer around the substrate. The user learns what feedback state, jobs, plugins, stopping conditions, waiting, verification, and condensation mean by watching the first behavior operate.

Minimum anatomy

Empty in domain content, not empty in architecture.

The foundation contains only the generic mechanisms needed to let the user shape what comes next.

Visible surface

A simple home or Wiki page, a feedback control available in context, and views for feedback and agent status.

Persistent state

Raw user input, page context, lifecycle state, agent interpretation, linked work, verification, and user acceptance remain inspectable.

Bounded behavior

A feedback-management plugin senses actionable work, preserves responsibility, waits safely, verifies completion, and supports reopening.

The developmental mechanism

The user grows the dashboard through the dashboard.

The first interaction surface becomes the mechanism through which later pages and behaviors are requested and refined.

1. Comment

The user describes a missing page, object, workflow, correction, question, or idea from the relevant context.

2. Interpret

The plugin preserves the raw input, determines actionability and authority, and asks when meaning is unclear.

3. Build

The agent performs bounded work, keeps responsibility visible, and explains the abstraction being added.

4. Verify and review

The result is tested, returned to the dashboard, accepted or reopened by the user, and condensed into useful learning.

Differentiation

Every clone can develop into a different cognitive organism.

The common substrate provides a developmental loop; the user supplies the operational world and evolutionary direction.

The agent adds pages and data structures in the user's terminology, introduces jobs only when work deserves persistence, adds plugins only for bounded repeated responsibilities, and makes authority and verification visible. The result is not a reskinned generic dashboard. It is a distinct user-owned lineage.

As the asset grows, the agent returns to Hadosh Academy technical writing and project examples for relevant building blocks, then teaches the user how each pattern has been adapted locally.

Companion curriculum

The project and its technical writing grow together.

Each mechanism becomes both reusable implementation evidence and an educational pattern for agents and users.
