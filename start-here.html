What This Site Is — and How to Use It

FIVE MINUTES. ZERO SETUP.

Hadosh Academy is an open technical and educational project about user-owned agent harnesses: how they work, how people can understand them, and how different implementations can grow around real work.

What Is a Seed Agent?

A Seed Agent is a local, inspectable harness around an LLM and a CLI runtime. The model supplies general reasoning. The runtime supplies tools and access to the environment. The harness supplies the durable structure that becomes specific to the user: jobs, memory, behavioral controls, cognitive modes, authority, verification, interfaces, and accumulated experience.

The important idea is continuity. A useful agent should not have to rediscover your work from scratch every time a model session begins. The harness keeps the parts that deserve to persist.

The model is rented intelligence. The harness is the layer you cultivate and own.

Who Is This For?

The site is written for people with valuable domain knowledge who want to understand and shape agentic systems without taking on the full implementation burden themselves. That can include researchers, founders, consultants, lawyers, project managers, educators, filmmakers, journalists, and technical builders.

What You Are — and Are Not — Expected to Do

The site uses real architectural terms because useful ownership requires some shared language. That does not mean ordinary users should hand-write the implementation.

You are not expected to

  • Write hooks, scripts, schemas, or configuration by hand.
  • Debug plugin source code as part of normal use.
  • Understand the internals of the language model.
  • Memorize platform-specific implementation details.
  • Become the maintainer of every low-level mechanism.

You are expected to

  • Explain your work and judgment clearly.
  • Learn enough vocabulary to describe the behavior you want.
  • Notice when the harness is wrong, incomplete, or overly rigid.
  • Understand the important compartments and authority boundaries of your own system.

The user learns the anatomy; the CLI agent can increasingly handle the syntax.

PowerPoint-Level Vocabulary Is Enough to Start

You need top-level concepts, not syntax. Think of a film director who understands “shot list,” “blocking,” and “wrap” without operating every camera.

Job

A durable unit of work with an objective, state, history, and completion path.

“Take on a job to compare these three patent families.”

Memory

Context the harness preserves because future work may need it.

“Remember that uncertainty must be reported separately from conclusions.”

Plugin

A bounded behavioral or operational capability with a clear objective and interface.

“Add a behavior that checks every report for unsupported claims.”

Phase

A compartment for a kind of cognition such as observing, planning, executing, verifying, or consolidating.

“Return to observation before changing the plan.”

What the Deep Essays Actually Teach

Part 1 develops the conceptual argument in plain language: why the model is not the whole agent, why structure matters, and why people need a vocabulary for the harness around the model.

Part 2 documents the first-generation private Claude Seed in detail. The B5–B8 series covers its always-on digital cortex, OPEVC phasic brain, plugin anatomy, and maturation from soft behavior to harder controls.

Those essays are valuable because they document a real implementation where these mechanisms coexisted. They are the technical lineage for the newer public implementations, not a rule that every future Seed must use the exact same files or mechanisms.

The Three Things Working Together

A personal Seed is easiest to understand as three cooperating layers.

Conversation

You explain your work, corrections, preferences, and new ideas. Conversation is the main way non-technical users steer the architecture.

CLI Runtime

Codex, Qwen Code, OpenCode, or another compatible runtime gives the model tools and access to the environment. The runtime is important, but it is not the whole identity of the harness.

Filesystem / Harness

Durable instructions, context, jobs, memory, plugins, tests, and other cognition live outside the model session in inspectable assets you can back up, version, and evolve.

You Can Change the Harness in Two Ways

Through conversation

Tell the agent what should change. A capable CLI agent can inspect the existing harness, propose the architectural change, implement it, test it, and show you what changed.

Through direct inspection

Open the files, read the state, inspect a rule, review a diff, or edit directly when you want. Technical users should never be locked out of their own customization layer.

The goal is not “no files.” The goal is that understanding the architecture does not require manually implementing every file.

Two Ways to Start Owning a Harness

Start from a mature public Seed

Clone a stable base, learn its vocabulary and boundaries, then cultivate its cognition and jobs around your own work.

Cultivate one from scratch

For direct individual or team work, begin thinner and build the architecture with the users involved, using earlier harnesses as pattern libraries and evidence rather than compulsory templates.

Why the Concepts Matter Even If You Never Touch Code

An agent you cannot steer precisely is difficult to own meaningfully. Vocabulary gives you words for what should be remembered, which behavior deserves a plugin, when a job needs a different phase, what requires verification, and which changes require your approval.

A small amount of architectural literacy can support years of more precise collaboration with a harness that keeps evolving around your work.
