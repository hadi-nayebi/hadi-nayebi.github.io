Context

Current definition

In Hadosh Academy, context is the active, bidirectional interface through which a model and harness influence one another. It is the bounded working surface containing information supplied for inference and the model-generated output returned from inference. At any moment, context is a mixture of harness-originated material—such as instructions, injections, retrieved memory, observations, tool results, state, constraints, and authority—and model-originated material—such as continuations, questions, reasoning traces, decisions, and action proposals. The harness constructs context by selecting, arranging, adding, removing, and formatting explicit information. The model interprets that context and extends or transforms it through inference. The harness then decides what model-generated material to display, persist, validate, execute, condense, reuse, or discard. This makes influence bidirectional without collapsing the two compartments: the harness influences the model through what it supplies, and the model influences the harness through what it generates. Context is not identical to memory or to a complete transcript. Parametric memory can influence output without appearing explicitly in context. Harness memory can remain stored without being loaded. Model-originated material can become harness state when it is deliberately preserved, while harness state can temporarily enter context when selected for an invocation. Provenance should remain visible even when material crosses the boundary. Different systems may expose different portions of cognition. Latent reasoning that never crosses the interface remains model-side; textual or otherwise inspectable reasoning that is exposed enters context and can be managed by local or provider-controlled harnesses. The purpose of the context boundary is not to impose one configuration, but to make the location and movement of information inspectable enough to evaluate and improve.
