Runtime

Current definition

A runtime is active execution machinery that turns stored capability and harness structure into running behavior. Because the word is overloaded, Hadosh Academy qualifies it when the distinction matters. A model runtime executes or provides model inference. An agent runtime activates and orchestrates harness mechanisms around that capability: it assembles selected context, carries sessions or events, exposes permitted tools, invokes models, applies available control points, and returns results and evidence for verification. A runtime is not the complete harness; durable instructions, memory, jobs, identity, authority, and history can remain while no runtime is active. A command-line interface may launch, attach to, or control a runtime, but the interface is not itself the execution machinery. Model and agent runtimes may be local, hosted, distributed, embedded, or composed across services. Their location, custody, enforcement capabilities, and failure boundaries should be explicit. Instructions can request behavior, but only runtime or other deterministic harness mechanisms can guarantee a block, protected action, atomic update, or enforced permission boundary.

Open questions

These are the parts of the definition that still need clarification.

  1. How should model-runtime and agent-runtime responsibility be reported when inference, orchestration, tools, and state span several services?

  2. Which enforcement capabilities are necessary before an agent runtime can honestly support consequential action?

  3. Which continuity state belongs to an active runtime, and which must remain in the durable harness so the agent can recover after execution stops?
